# Q&A를 주고받는 대화로 — 설계

작성일: 2026-09-04

## 배경

지금 Q&A는 질문 하나에 답변 하나다. `qna.answer` 칸에 교사가 쓴 답변이 들어가고,
그걸로 끝이다. 학생이 "그럼 3번은요?" 하고 되묻거나 교사가 설명을 덧붙일 방법이 없다.

교사에게서 "답변 완료된 것에 학생이 추가 질문을 달거나 내가 추가 답변을 달 수 있으면
좋겠다"는 요청이 왔다.

### 정한 것

| 항목 | 결정 |
|------|------|
| 대화 횟수 | **제한 없음.** 학생·교사가 번갈아 계속 쓸 수 있다 |
| 사진 | **학생·교사 모두** 붙일 수 있다 (글마다 최대 3장) |
| 알림 | 학생이 추가 질문을 올리면 **새 질문과 똑같이** 담당 교사 폰으로 간다 |

교사가 쓴 글에는 알림이 없다. 학생 계정에는 푸시 구독이 없기 때문이다
(알림 켜기는 교사·관리자에게만 보인다). 학생에게 알리는 건 별도 작업이다.

## 데이터 구조

두 갈래를 놓고 비교했다.

| 방식 | 판단 |
|------|------|
| **별도 표 `qna_messages`** | **채택.** 글마다 작성자·시각·사진이 따로 남고, 알림 웹훅을 이 표의 INSERT에 걸 수 있다 |
| `qna.messages` jsonb 배열 | 표를 안 만들어도 되지만, 학생과 교사가 거의 동시에 쓰면 배열을 통째로 저장하느라 한쪽 글이 덮여 사라진다. 알림을 걸 INSERT 지점이 없어 `qna` UPDATE에 걸면 답변 수정에도 알림이 간다 |

```
qna              (스레드)   — 지금 그대로. 말머리, 학생, 첫 질문 내용·사진
qna_messages     (주고받는 글)
  id           bigint  생성 키
  qna_id       bigint  → qna(id) on delete cascade
  author_id    uuid    → profiles(id) on delete set null
  author_role  text    'student' | 'teacher'
  content      text    not null
  image_paths  jsonb   not null default '[]'  (최대 3장)
  created_at   timestamptz not null default now()
```

**첫 질문은 `qna`에 그대로 둔다.** 목록 화면이 미리보기를 보여줄 때 표를 두 개 뒤지지
않아도 되고, 옮길 데이터도 줄어든다. 화면에서는 첫 질문 + 메시지들을 하나의 대화로 그린다.

**`author_role`을 따로 저장하는 이유** — 나중에 그 사람의 역할이 바뀌어도(교사→관리자,
또는 계정 삭제로 `author_id`가 null이 되어도) 그때 누가 쓴 글이었는지가 남아야 한다.
화면의 좌우 배치와 답변 완료 판정이 이 값을 본다.

## 답변 완료 / 대기 판정

지금은 `!q.answer` 하나로 판정한다(`qnaAccess.js:50`). 이걸 **"마지막 글을 누가 썼나"**로
바꾼다.

| 마지막 글 | 상태 |
|-----------|------|
| 없음 (첫 질문뿐) | 답변 대기 |
| 학생 | 답변 대기 — 추가 질문도 답을 기다리는 것이다 |
| 교사 | 답변 완료 |

`qnaStatus(question, messages) -> 'waiting' | 'answered'` 순수 함수로 만든다.
목록 배지, 미답변 건수, 대시보드가 **전부 이 함수 하나를 쓴다.** 지금처럼 화면마다
`!q.answer`를 따로 적으면 판정 규칙이 바뀔 때 빠뜨리는 곳이 생긴다.

## 기존 답변 옮기기

`qna.answer`가 있는 행을 `qna_messages`의 교사 메시지로 옮긴다.

```
content     ← qna.answer
author_id   ← qna.answered_by
author_role ← 'teacher'
created_at  ← qna.answered_at
```

옮긴 뒤 `answer`·`answered_at`·`answered_by`를 **비운다.** 두 곳에 답이 남으면 어느 쪽이
진짜인지 헷갈리고, 화면이 둘 다 그리면 답변이 두 번 보인다.

칸 자체는 남겨둔다. 문제가 생겼을 때 되돌릴 여지를 두고, 안정되면 나중에 지운다.

## 메시지 수정·삭제

어제 만든 "답변 수정·삭제"가 "메시지 수정·삭제"로 확장된다. `deleteAnswer`는 없어진다.

**수정과 삭제의 규칙이 다르다.**

| 역할 | 고칠 수 있는 글 | 지울 수 있는 글 |
|------|----------------|----------------|
| 학생 | 본인이 쓴 글 | 본인이 쓴 글 |
| 교사·관리자 | **본인이 쓴 글만** | 그 스레드의 모든 글 |

교사가 학생 글도 지울 수 있어야 하는 이유 — 학생이 부적절한 사진을 올렸을 때 지울
사람이 필요하다. 질문 전체를 지우면 대화가 통째로 사라진다.

반면 **남이 한 말을 고쳐 쓰는 건 지우는 것과 다른 얘기다.** 학생이 하지 않은 말이
학생 이름으로 남게 된다. 문제가 있는 글은 지우면 된다.

사진은 수정 대상이 아니다. 바꾸려면 글을 지우고 다시 쓴다. 수정 중에 사진까지 갈아
끼우게 만들면 중간에 실패했을 때 글과 사진이 어긋난 상태로 남는다.

메시지를 지우면 붙은 사진도 함께 지운다. 질문 삭제와 같은 순서다 — **글을 먼저 지우고
사진을 나중에.** 반대로 하면 사진 삭제 후 글 삭제가 실패했을 때 이미지가 깨진 글이 남는다.

## 사진

메시지 사진도 `qna-images` 버킷을 쓰고, 경로도 지금과 같이 **그 스레드 학생의 폴더**
(`{studentId}/{token}.jpg`)에 넣는다. 폴더를 학생 기준으로 통일해야 읽기 정책
(`can_see_qna_author`)이 그대로 동작한다.

다만 지금 쓰기 정책 `qna_img_write`는 "본인 폴더만"이라 **교사가 사진을 올릴 수 없다.**
교사·관리자가 볼 수 있는 학생의 폴더에 쓸 수 있게 넓힌다.

## 알림

`qna_messages` INSERT에 웹훅을 하나 더 건다.

```
학생이 추가 질문 등록
  → Supabase가 qna_messages INSERT 감지
  → POST /api/notify-qna-message  (비밀 헤더는 기존과 같은 값)
  → author_role이 'student'일 때만 진행 (교사 글은 받을 학생 구독이 없다)
  → qna_id로 부모 질문을 찾아 student_id를 얻는다
  → notifyTargets로 담당 교사를 고른다 (기존 함수 그대로)
  → "홍길동 · 추가 질문"
```

`notifyTargets`·`isDeadSubscription`·`endpointsToRemove`는 `api/notify-qna.js`에 이미
있다. 그대로 가져다 쓴다.

## 화면

**목록** — 지금과 같다. 배지만 `qnaStatus`가 정한다. 사진 표시는 첫 질문 기준을 유지한다.

**대시보드** — 학생 화면의 "Q&A 답변" 카드가 `q.answer`가 있는 질문을 `answeredAt` 순으로
고른다(`Dashboard.jsx:282`). 답변을 메시지로 옮기면 그 조건이 전부 거짓이 되어 카드가
빈다. **마지막 교사 메시지 기준으로 고르도록** 함께 바꾼다. 교사 화면의 미답변 건수도
`qnaStatus`를 쓴다.

**상세** — 첫 질문 아래에 메시지들이 시간순으로 이어진다. 학생 글과 교사 글이 구분되게
그린다(교사 글은 지금 답변처럼 남색 배경). 맨 아래에 **글쓰기 칸**이 있고, 학생·교사 모두
같은 칸을 쓴다. 사진 첨부는 질문 작성 화면의 부품을 그대로 재사용한다.

학생 화면에서 교사 이름은 표시하지 않는다(지금도 "선생님 답변"이라고만 나온다).

## 테스트

- 마지막 글이 학생이면 답변 대기, 교사면 답변 완료, 글이 없으면 대기
- 미답변 건수가 같은 규칙으로 세어진다
- 학생은 본인 글만 지울 수 있다 / 교사는 그 스레드의 모든 글을 지울 수 있다
- 수정은 본인 글만 — 교사여도 학생 글은 고칠 수 없다
- 메시지 등록 실패 시 화면에 남고 사유를 보여준다
- 알림 문구에 글 내용이 들어가지 않는다 (잠금화면 노출 방지)
- 교사가 쓴 글에는 알림을 보내지 않는다

## 사람이 해야 하는 준비

1. `docs/qna-messages.sql` 실행 — 표, RLS 정책, 기존 답변 옮기기, 사진 쓰기 정책 확대
2. Supabase 웹훅 추가 — `qna_messages` INSERT → `https://www.sumunjae.com/api/notify-qna-message`,
   헤더 `x-webhook-secret`은 기존 웹훅과 같은 값

## 이번 범위에서 뺀 것

- 교사가 답을 달았을 때 **학생에게 알림** (학생 계정에 푸시 구독 기능이 없다. 붙이려면
  학생 화면에도 알림 켜기를 넣어야 하고, 그건 별도 작업이다)
- 읽음 표시 / 안 읽은 글 개수
- 메시지 수정 이력
