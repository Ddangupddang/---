# 교사에게 담당 반만 보이게 하기 — 설계

작성일: 2026-08-21

## 배경

지점이 3곳으로 늘면서 교사가 다른 지점 학생까지 전부 보는 상태가 문제가 됐다.
권한 기준은 지점이 아니라 **담당 반**으로 잡았다. 반은 이미 `classes.teacher_id`로
교사와 연결돼 있고, 겸임·특강처럼 지점 경계를 넘는 경우도 반 배정이면 그대로 흡수된다.

지금은 대시보드(`Dashboard.jsx`)와 출결(`Attendance.jsx`)만 담당 반으로 거르고,
나머지 화면은 `classes` 전체를 그대로 쓴다. 즉 교사에게 전 지점 학생이 다 보인다.

## 규칙

| 역할 | 보이는 범위 |
|------|-------------|
| 관리자 | 전체 (지금과 동일) |
| 교사 | 담당 반(`classes.teacher_id === user.id`)과 그 반 학생 |
| 학생 | 본인 반 (지금과 동일) |

담당 반이 아닌 것은 **목록에 아예 나타나지 않는다.** 조회만 되는 중간 상태는 두지 않는다.

## 구조

권한 규칙을 `src/utils/classAccess.js` 순수 함수에 모은다. 각 화면이 같은 필터를
따로 적어두면 규칙이 바뀔 때 빠뜨리는 곳이 생긴다.

```js
visibleClasses(classes, user)              // 역할에 따라 보이는 반 목록
visibleClassIds(classes, user)             // 위의 id 배열
visibleStudents(students, classes, user)   // 보이는 반에 속한 학생
canSeeClass(classes, user, classId)        // 특정 반 접근 가능 여부
```

대시보드·출결에 흩어져 있던 인라인 필터도 이 함수로 교체한다 (동작은 동일).

## 화면별 적용

| 화면 | 적용 내용 |
|------|-----------|
| 대시보드 · 출결 | 공통 함수로 교체 (동작 변화 없음) |
| 학생 관리 | 담당 반 학생만. 반 관리 탭도 담당 반만 |
| 성적 | 담당 반 탭만 |
| 진도 리포트 | 담당 반 리포트만. 작성 시 반 선택도 담당 반만 |
| 주간 리포트 | 담당 반만 |
| 영상 | 담당 반 영상만. 등록 시 대상 반도 담당 반만 |
| 테스트 | 담당 반 테스트만 |
| Q&A | 담당 반 테스트에 달린 질문만 |
| 공지 | 담당 반 대상 공지만. **학원 전체 공지(대상 미지정)는 계속 보인다** |
| 계정 관리 | 변경 없음 (관리자 전용) |
| 과제 | **이번 작업 제외** — 다른 세션이 같은 파일을 수정 중 |

## 담당 반이 없는 교사

배정 전 교사 계정은 화면이 텅 빈다. 고장과 구분이 안 되므로
"담당 반이 없습니다. 관리자에게 반 배정을 요청하세요" 안내를 띄운다.

## 한계 — 화면 필터이지 데이터 잠금이 아니다

브라우저가 Supabase에서 전체 데이터를 받아온 뒤 화면에서 고르는 구조다.
개발자도구를 다룰 줄 아는 사람이면 다른 반 자료도 꺼내볼 수 있다.
실제 차단은 Supabase RLS 정책이 필요하며 별도 작업으로 둔다.

이 순서인 이유: 화면 필터가 먼저 있어야 RLS를 켰을 때 안 보이는 것이
정상인지 판단할 수 있다.

## 테스트

- `classAccess` 순수 함수 단위 테스트 (역할 3종, 담당 반 없음, 반이 삭제된 학생 등)
- 각 화면은 기존 테스트가 깨지지 않는지로 확인하고, 필터가 핵심인 화면은 렌더 테스트를 추가
