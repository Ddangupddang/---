# 디자인 시스템 리뉴얼 — 정보제공 사이트와 브랜드 통일

작성일: 2026-08-13
상태: 설계 승인됨 (구현 계획 대기)

---

## 1. 배경 & 목적

두 가지 불만에서 출발했다.

1. **촌스럽고 예쁘지 않다** — 마감 완성도가 낮다
2. **화면마다 생김새가 다르다** — 같은 버튼·카드인데 페이지마다 모양이 제각각

둘 다 원인이 하나다. **디자인 시스템이 없다.**

`src/constants/colors.js`에 색이 정의돼 있지만 실제로는 거의 쓰이지 않고,
`bg-[#2B2B2B]` 같은 하드코딩이 **39개 파일에 약 380곳** 흩어져 있다.
Tailwind v4를 쓰면서 설정 파일이 없어 토큰을 정의할 자리조차 없다.
그래서 지금은 "파랑 조금만 진하게"가 380곳 수정이 된다.

같은 학원의 **정보제공 사이트**(`~/Documents/developments/수문재-정보제공`)에는
이미 잘 정리된 디자인 시스템이 있다. 학부모가 보는 얼굴과 내부 도구가 따로 노는 것도
이상하므로, **그 시각 언어를 가져와 통일한다.**

다만 정보제공은 *읽는 사이트*, 학생관리는 *일하는 도구*다.
색·글꼴·형태는 공유하되 **밀도와 정보 위계는 도구에 맞게** 조정한다.

## 2. 확정 사항

브라우저 목업으로 4라운드 비교해 확정했다.

| 항목 | 결정 | 근거 |
|---|---|---|
| 제목 글꼴 | **본명조 (Noto Serif KR)** | 나눔명조는 큰 글씨에서 획이 헐거워 "유치한" 인상. 본명조는 획이 단단하고 굵기가 고르다 |
| 본문 글꼴 | **Pretendard** | 정보제공 사이트와 동일 |
| 모서리 | **4px** | 표·숫자가 많은 관리 도구에 또렷하고 정돈된 인상. 세리프 제목과의 대비도 좋다 |
| 사이드바 | **밝은 회색 + 선택 항목만 진한 남색** | 화면 전체가 가볍고 정보제공의 흰 느낌과 이어진다 |
| 표 스타일 | **숫자 + 각진 미니 막대** | 숫자를 읽지 않고 훑어도 비율이 스캔된다 |
| 글자 크기 | **크게** (제목 30~31 / 표 16) | 기존 11.5~14px는 작아 눈에 안 들어왔다 |
| 채도 | **낮춘다** | 파스텔 파랑이 유치함의 주원인. 진한 남색으로 교체 |
| 그림자 | **쓰지 않는다** | 1px 선으로만 구분 (정보제공과 동일) |

**기능·이름·사이드바 메뉴 구조·라우트는 하나도 바꾸지 않는다.** 순수 시각 변경이다.

## 3. 디자인 토큰

Tailwind v4의 `@theme` 디렉티브로 `src/index.css`에 정의한다.
v4는 설정 파일 없이 CSS에서 토큰을 선언하면 유틸리티 클래스가 자동 생성된다.

### 3.1 색

| 토큰 | 값 | 용도 |
|---|---|---|
| `--color-ink` | `#22242A` | 본문 글자, 기본 버튼 배경 |
| `--color-ink-soft` | `#767884` | 보조 설명 글자 |
| `--color-ink-mute` | `#8E9099` | 더 약한 보조 (문항 수, 날짜) |
| `--color-ink-faint` | `#B4B7C0` | 비활성, `—`(기록 없음) |
| `--color-navy` | `#2B3A55` | 강조·선택 상태·막대 |
| `--color-navy-soft` | `#E7EBF2` | 뱃지 배경 (남색 계열) |
| `--color-danger` | `#A63A2C` | 결석·부진·경고 |
| `--color-danger-soft` | `#F6E9E7` | 경고 뱃지·배너 배경 |
| `--color-warn` | `#8A6320` | 주의 (중간 점수) |
| `--color-warn-soft` | `#F4EEE2` | 채점중 뱃지 배경 |
| `--color-surface` | `#FFFFFF` | 본문 바탕, 카드 |
| `--color-surface-alt` | `#F5F6F9` | 사이드바, 표 머리 |
| `--color-line` | `#DFE1E7` | 테두리 |
| `--color-line-soft` | `#EFF0F4` | 표 행 구분선 |

기존 `success`/`warning`은 위 토큰으로 흡수한다.

**`src/constants/colors.js`는 삭제한다.** 확인해 보니 이 파일은 **어디에서도 import되지 않는다** —
`CLAUDE.md`의 "색상은 constants/colors.js에서 불러와서 사용" 규칙이 지켜진 적이 없고,
모두가 hex를 직접 박아 왔다. 지키지 않는 규칙과 죽은 파일을 남겨두면 다음 사람도 똑같이 헷갈린다.

대신 `CLAUDE.md`의 해당 규칙을 **"색상은 `index.css`의 `@theme` 토큰 클래스를 쓴다
(`bg-ink`, `text-danger` 등). hex를 직접 쓰지 않는다"**로 갱신한다.
Tailwind 유틸리티가 곧 단일 출처가 되므로 JS 상수 파일은 필요 없다.

### 3.2 글꼴

```
--font-sans:  'Pretendard', system-ui, -apple-system, sans-serif
--font-serif: 'Noto Serif KR', serif
```

- 본문·표·버튼·입력: `sans`
- **페이지 제목, 카드 제목, 로고: `serif`**
- 숫자가 세로로 정렬돼야 하는 표 셀: `font-variant-numeric: tabular-nums`

기존 Noto Sans KR import는 제거하고 Pretendard + Noto Serif KR로 교체한다.

### 3.3 크기

| 용도 | 크기 | 굵기 |
|---|---|---|
| 페이지 제목 | 30px | 700 (serif) |
| 페이지 설명 | 14px | 400 |
| 카드/섹션 제목 | 16~18px | 700 |
| 표 헤더 | 11.5px | 700, `letter-spacing: .08em` |
| 표 본문 | 16px | 400~600 |
| 뱃지·라벨 | 12px | 700 |
| 보조 설명 | 13px | 500 |

### 3.4 형태

```
--radius-sm: 2px   /* 뱃지 */
--radius:    4px   /* 버튼, 카드, 입력, 표 컨테이너 */
```

그림자는 쓰지 않는다. 구분은 항상 `1px solid var(--color-line)`.

## 4. 공통 컴포넌트

"화면마다 생김새가 다른" 문제는 여기서 해결된다.
`src/components/ui/`에 만들고, 기존 화면들이 이걸 쓰도록 바꾼다.

| 컴포넌트 | 역할 | 변형 |
|---|---|---|
| `Button` | 버튼 | `primary`(먹색) / `accent`(남색) / `ghost`(테두리) / `disabled` |
| `Badge` | 상태 라벨 | `navy` / `danger` / `warn` / `neutral` |
| `Card` | 흰 배경 + 1px 테두리 + 4px 모서리 | — |
| `PageTitle` | 세리프 제목 + 설명 | — |
| `DataTable` | 표 껍데기 (헤더 스타일·행 구분선·경고 행 왼쪽 세로선) | — |
| `MiniBar` | 각진 미니 막대 | 색은 prop |
| `Alert` | 경고 배너 (왼쪽 3px 세로선) | `danger` / `info` |

각 컴포넌트는 순수 표시 컴포넌트로 만든다 — `useData`/`useAuth`를 쓰지 않고
props만 받는다. 테스트가 쉽고, 어디서든 재사용된다.

## 5. 적용 범위와 순서

전체 39개 파일 · 약 380곳의 색과 238곳의 모서리·그림자가 대상이다.
한 번에 다 바꾸면 되돌리기 어려우므로 **아래에서 위로** 쌓는다.

1. **토큰 정의** — `index.css`에 `@theme`, 글꼴 교체, `colors.js` 삭제, `CLAUDE.md` 규칙 갱신
2. **공통 컴포넌트 신설** — `src/components/ui/*` + 각각의 테스트
3. **셸 적용** — `Layout` / `Sidebar` / `Header` / `BottomNav` (가장 눈에 띄는 곳)
4. **화면 적용** — 페이지 14개를 공통 컴포넌트로 교체. 사용 빈도 순:
   주간 리포트 → 과제 → 출결 → 학생 관리 → 성적 → 테스트 → 나머지
5. **잔여 정리** — 남은 하드코딩 색 검색해 토큰으로 치환

각 단계 끝에서 전체 테스트·lint·빌드가 통과해야 다음으로 넘어간다.

## 6. 테스트 영향

색상 클래스명을 단언하는 테스트가 **4곳** 있다. 토큰으로 바꾸면 클래스명이 달라져 깨진다.

| 파일 | 줄 | 현재 단언 |
|---|---|---|
| `ChoiceGrid.test.jsx` | 37 | `toMatch(/bg-\[#2B2B2B\]/)` |
| `TeacherHomeworkStatus.test.jsx` | 124 | `toContain('#C0392B')` |
| `TeacherHomeworkCreate.test.jsx` | 167, 168 | `toContain('#2B2B2B')` |

**대응**: hex 대신 토큰 클래스명(예: `bg-ink`)을 단언하도록 고친다.
색이 아니라 "선택됨/오답 표시"라는 의미를 검증하는 것이 원래 의도이므로,
가능하면 `data-selected` 같은 속성 단언으로 바꿔 색 변경에 영향받지 않게 한다.

그 외 248개 테스트는 기능 테스트라 영향받지 않아야 한다.
**하나라도 깨지면 그건 시각 변경이 동작을 건드렸다는 신호이므로 멈추고 조사한다.**

## 7. 위험 요소

- **폰트 로딩** — Pretendard는 jsDelivr CDN, Noto Serif KR은 Google Fonts에서 받는다.
  네트워크가 느리면 글자가 늦게 뜬다. `display=swap`으로 본문이 먼저 보이게 한다.
- **한 번에 너무 많이** — 39개 파일을 한 커밋에 바꾸면 리뷰도 롤백도 불가능하다.
  5단계로 나누고 단계마다 커밋한다.
- **기능 변경 유혹** — 화면을 만지다 보면 "이 버튼 위치도 바꿀까" 싶어진다.
  **하지 않는다.** 이번 작업은 순수 시각 변경이다.
