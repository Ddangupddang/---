# 복수 정답(다중선택) — 테스트·과제 공통

작성일: 2026-08-19
상태: 설계 승인됨 (구현 계획 대기)

---

## 1. 배경 & 목적

「모두 고르시오」형 문항을 출제할 수 없다. 지금은 문항당 정답이 문자열 하나(`answer: '③'`)이고,
채점은 `studentAnswer === q.answer` 단순 비교다. 교사가 정답을 하나만 지정할 수 있고,
학생도 선지를 하나만 고를 수 있다.

교사·관리자가 정답을 여러 개 지정하고, 학생도 여러 개 체크해 제출할 수 있게 한다.

---

## 2. 확정 사항

| 항목 | 결정 | 근거 |
|---|---|---|
| 복수 정답의 뜻 | **「모두 고르시오」형(다중선택)** | 정답이 ①③이면 학생도 ①③을 다 골라야 정답 |
| 채점 | **전부 맞아야 정답. 부분점수 없음** | 덜 골라도 오답, 더 골라도 오답 |
| 적용 범위 | **과제와 테스트 둘 다** | 둘이 같은 `ChoiceGrid`를 쓴다. 한쪽만 고치면 두 화면의 동작이 갈린다 |
| 문항 구분 | **모든 문항을 토글식으로**. 다중선택 전용 플래그를 두지 않는다 | 보통 문항은 하나만 켜면 되고, 시험지에 "모두 고르시오"가 적혀 있어 화면에 따로 표시할 필요가 없다 |
| 키보드 | **숫자키 1~5는 토글만(제자리), Enter·↓로 다음 문항** | 다중선택을 키보드로 넣을 수 있어야 한다 |

**기능·화면 배치·문구는 바꾸지 않는다.** 입력 방식과 채점 기준만 바뀐다.

---

## 3. 데이터 — 마이그레이션 없음

선지 `①②③④⑤`는 각각 한 글자(U+2460–U+2464)다. 정답을 **선지 글자를 이어 붙인 문자열**로 저장한다.

```
정답 ③ 하나   → '③'      (지금과 완전히 동일)
정답 ①과 ③    → '①③'
```

이 방식의 이점:

- **기존 데이터가 그대로 유효하다.** `'③'`은 원소 하나짜리 집합으로 읽힌다
- **DB 스키마를 건드리지 않는다.** 과제(`homework_questions.answer` text)와
  테스트(`tests.questions` jsonb 안의 `answer`) 양쪽 다
- **기존 제출 기록도 그대로 채점된다.** 학생 답안(`answers[].answer`)도 같은 규칙

`[...'①③']` → `['①', '③']`로 분해된다. 서러게이트 페어가 아니므로 안전하다.

---

## 4. 비교 함수

집합 비교를 순수 함수 하나로 모은다. `src/utils/answerSet.js`:

```js
sameChoiceSet('①③', '③①')   // true  — 순서 무관
sameChoiceSet('①③', '①')     // false — 덜 고름
sameChoiceSet('①③', '①②③')  // false — 더 고름
sameChoiceSet('', '①')        // false — 미입력
sameChoiceSet(null, null)     // false — 둘 다 없으면 정답으로 치지 않는다
```

**과제 채점과 테스트 채점이 같은 함수를 쓴다.** 지금은 두 곳이 각자 `===`로 비교하고 있어,
한쪽만 고치면 같은 학원에서 두 채점 기준이 갈라진다.

`answerSet.js`를 따로 두는 이유: `homework.js`에 넣으면 테스트 채점이 과제 유틸을 import하게 되어
의존 방향이 어색해진다. 둘 다 쓰는 것은 둘 다 모르는 곳에 둔다.

---

## 5. ChoiceGrid — 토글

과제와 테스트가 같은 컴포넌트를 쓰므로 **여기 한 곳만 고치면 양쪽에 적용된다.**

| 동작 | 지금 | 바뀐 후 |
|---|---|---|
| 선지 클릭 | 그 선지로 **교체** | **토글** (켜기/끄기) |
| 숫자키 1~5 | 선택 + 다음 문항으로 자동 이동 | **토글만, 제자리** |
| Enter | (없음) | **다음 문항으로** |
| ↓ → | 다음 문항 | 그대로 |
| ↑ ← | 이전 문항 | 그대로 |

`onChange(number, nextValue)` 시그니처는 그대로 두고, `nextValue`에 **토글 후의 전체 문자열**을 넘긴다.
호출부(`TeacherHomeworkCreate`, `StudentHomeworkView`, `Tests`)는 지금도 받은 값을 그대로 저장하므로
변경이 필요 없다.

토글 결과 문자열은 **선지 순서(①②③④⑤)로 정렬**해 저장한다. `③`을 먼저 누르고 `①`을 눌러도 `'①③'`이 된다 —
저장된 값이 입력 순서에 따라 달라지면 나중에 눈으로 비교하기 어렵다.

### 결과 화면(mode='result')

`cellResult`의 판정을 `===`에서 **포함 여부**로 바꾼다:

```
picked   = 학생 답에 이 선지가 있는가
isAnswer = 정답에 이 선지가 있는가
```

네 상태(`correct`/`wrong`/`answer`/`none`)의 의미와 색은 그대로다.

## 6. 입력 완료 판정

지금은 "답이 있는 문항 수 = 전체 문항 수"로 저장·제출 버튼을 켠다.
토글이 되면 **다 껐을 때 빈 문자열**이 되므로, 빈 문자열을 미입력으로 세도록 고친다.

- `TeacherHomeworkCreate.jsx` — `canSave`
- `StudentHomeworkView.jsx` — `allAnswered`, 그리고 "n/m 입력됨" 카운터

고치지 않으면 아무것도 고르지 않은 문항이 입력된 것으로 세어져 저장·제출이 열린다.

## 8. 테스트 계획

**`answerSet.test.js`** — 순서 무관 동치, 덜 고름, 더 고름, 빈 값, `null`, 한 개끼리(기존 동작 회귀)

**`ChoiceGrid.test.jsx`** — 클릭이 토글된다(같은 선지 두 번 → 꺼짐), 여러 선지를 켤 수 있다,
저장 값이 선지 순서로 정렬된다, 숫자키가 제자리에서 토글한다, Enter가 다음 문항으로 이동한다,
result 모드에서 다중 정답의 네 상태가 바르게 표시된다

**기존 테스트** — 265개가 그대로 통과해야 한다. 한 개짜리 정답의 동작이 바뀌지 않았다는 뜻이다.
깨지면 기존 단일 선택 흐름을 건드렸다는 신호이므로 멈추고 조사한다.

## 9. 범위 밖 (YAGNI / 후속)

- 부분점수 (①③ 중 ①만 맞히면 절반) — 지금은 전부 맞아야 정답
- 문항별 "다중선택" 플래그와 「2개 선택」 안내 표시
- 주관식(`type: 'sa'`) 문항 — 이번 변경과 무관
- 정답 개수 검증 (교사가 5개를 다 켜는 것을 막지 않는다)

---

## 10. 알아둘 점

학생이 실수로 두 개를 켜면 오답이 된다. 부분점수가 없으므로 보통 문항에서 잦은 실수가 되면
학생 화면에 "2개 선택됨" 표시를 넣는 것을 후속으로 검토한다. 지금은 넣지 않는다 —
실제로 문제가 되는지 보고 결정하는 편이 낫다.
