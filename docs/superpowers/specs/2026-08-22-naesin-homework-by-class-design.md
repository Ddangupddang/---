# 내신 과제를 반별로 + 학생 검색 — 설계

작성일: 2026-08-22

## 배경

내신 과제는 지금 **학년** 단위로 나간다. 세트가 `(종류, 대상, 주차)`로 하나씩 있고
내신은 대상이 학년(중1~고3), 정시는 레벨(1~3)이다. 학생은 자기 `grade` /
`jeongsi_level`로 자동 매칭되며 반은 관여하지 않는다.

현장 요구는 **반마다 진도가 달라 과제도 반별로 나가야 한다**는 것이다.
정시는 지금처럼 레벨로 묶는 게 맞아 그대로 둔다.

## 결정

내신은 반별로 **완전히 교체**한다. 학년 선택은 내신 출제 화면에서 사라진다.
정시는 레벨 유지.

## 데이터

`homework_sets`에 `class_id`(nullable) 추가.

- 내신: `class_id`로 대상을 정한다. `target`은 쓰지 않는다
- 정시: `target`(레벨)을 그대로 쓴다. `class_id`는 비어 있다

중복 방지는 기존 `unique (category, target, week_start)`를 걷어내고 둘로 나눈다.

- 내신: `unique (class_id, week_start) where category = 'naesin'`
- 정시: `unique (target, week_start) where category = 'jeongsi'`

**기존 데이터는 옮기지 않는다.** 과거 내신 세트는 `class_id`가 빈 채 남고,
매칭이 학년으로 떨어져 지금처럼 동작한다. 학년 하나가 여러 반에 걸쳐 있어
1:N 이관이 애매하고, 지난 기록을 굳이 바꿀 이유도 없다.

## 매칭

학생↔과제 판정은 `matchesStudent(set, student)` 한 곳에 있다. 여기만 바꾼다.

```
내신: set.classId가 있으면  → set.classId === student.classId
      set.classId가 없으면  → set.target === student.grade   (과거 세트)
정시: 지금과 동일           → set.target === student.jeongsiLevel
```

이 함수를 주간 리포트와 과제 요약이 함께 쓰므로 그쪽은 저절로 따라온다.

## 화면

| 화면 | 바뀌는 것 |
|------|-----------|
| 과제 출제 | 내신 대상 선택이 학년 → 반 (교사는 담당 반만) |
| 제출 현황 | 내신 그룹 탭이 학년 → 반 |
| 과제 리포트 | 내신 그룹 탭이 학년 → 반 |
| 과제 목록 | 내신 세트는 담당 반 것만 |
| 해설 파일 | 저장 경로 키를 반 기준으로 |

정시 화면은 전부 그대로다.

## 받아들이는 한계

- **반이 없는 학생은 내신 과제를 못 받는다.** 지금은 학년만 있으면 받았다.
  적용 전에 반 미배정 학생을 확인해야 한다
- **과거 학년별 세트는 교사의 제출 현황·리포트 탭에서 보이지 않는다.**
  탭이 반 기준이 되기 때문이다. 학생 화면과 주간 리포트에서는 계속 보인다
- 출제 횟수가 반 수만큼 늘어난다. 부담이 크면 "다른 반 과제 복사"를 나중에 붙인다

## 곁들이는 작업 — 학생 검색

학생 관리 목록에 이름·연락처로 걸러내는 검색창을 넣는다. 반 필터와 함께 걸린다.

검색 중에는 순서 바꾸기(드래그)를 막는다. 걸러진 일부만 놓고 순서를 바꾸면
보이지 않는 학생들과 순서가 뒤엉킨다.

## 테스트

- `matchesStudent` — 반 기준 매칭, 과거 세트의 학년 폴백, 반 없는 학생, 정시 무변화
- 학생 검색 — 이름 일부로 걸러짐, 반 필터와 함께 적용, 검색 중 드래그 핸들 없음
