# RLS 적용 절차와 확인 목록

서버가 남의 반 데이터를 아예 내주지 않게 만드는 작업이다.
지금까지의 화면 필터는 눈에서 가리는 것이었고, 이건 서버에서 막는 것이다.

## 적용 순서

1. **한가한 시간에 한다.** 수업 중이나 출석 체크 시간대는 피한다.
   문제가 생기면 되돌리는 데 1분이면 되지만, 그 사이 화면이 빌 수 있다.
2. Supabase 대시보드 → SQL Editor → `docs/rls-policies.sql` 전체를 붙여넣고 Run
3. 아래 확인 목록을 순서대로 돌린다
4. 하나라도 어긋나면 **`docs/rls-rollback.sql`을 실행해 즉시 되돌리고**, 무엇이
   안 됐는지 알려준다

> 되돌리기는 언제든 안전하다. 데이터가 지워지거나 바뀌지 않고, 정책만 원래대로 돌아간다.

## 확인 목록

계정 세 개(관리자 / 반이 배정된 교사 / 학생)로 로그인해 확인한다.
**하나라도 "안 보임"이 나오면 안 되는 항목에 표시했다.**

### 관리자
- [ ] 로그인된다
- [ ] 학생 관리 — 전 지점 학생이 모두 보인다
- [ ] 반 관리 — 모든 반이 보이고, 반 추가·수정·삭제가 저장된다
- [ ] 계정 관리 — 교사 계정 목록이 보이고, 계정 생성이 된다
- [ ] 출결 — 상태를 눌러 바꾼 뒤 **새로고침해도 유지된다** (저장 실패는 새로고침해야 드러난다)
- [ ] 성적 입력 후 새로고침해도 남아 있다
- [ ] 공지 작성 → 목록에 뜬다
- [ ] 진도 리포트 작성 → 목록에 뜬다
- [ ] 과제 출제 → 목록에 뜬다

### 교사 (담당 반이 있는 계정)
- [ ] 로그인된다
- [ ] 대시보드에 담당 반이 보인다
- [ ] 학생 관리 — **담당 반 학생만** 보인다 (다른 지점 학생이 보이면 실패)
- [ ] 출결 — 담당 반 학생 출결을 바꾸고 새로고침해도 유지된다
- [ ] 성적 입력 후 새로고침해도 남아 있다
- [ ] 주간 리포트 — 담당 반이 열리고 코멘트가 저장된다
- [ ] 공지 작성 — 대상 반에 담당 반만 나오고, 작성이 저장된다
- [ ] 학원 전체 공지(관리자가 모든 반 대상으로 쓴 것)가 보인다
- [ ] 과제 제출 현황 — 담당 반 학생만 나온다
- [ ] Q&A — 담당 반 테스트 질문에 답변이 저장된다

### 학생
- [ ] 로그인된다
- [ ] 대시보드가 뜬다
- [ ] **출석 체크가 된다** (학원 WiFi에서, 누른 뒤 새로고침해도 출석 유지)
- [ ] 내 성적이 보인다
- [ ] 과제 제출이 저장된다
- [ ] 영상이 보이고 댓글이 달린다
- [ ] 공지가 보인다

### 차단 확인 (이건 "안 되는" 게 정상)
- [ ] 교사 계정으로 다른 지점 학생이 어디에도 안 보인다
- [ ] 학생 계정에서 같은 반 친구의 연락처·성적이 보이지 않는다

## 이 작업이 다루지 않는 것

- **과제 해설 파일(Storage)** — 파일 저장소는 별도 정책 체계라 그대로 뒀다.
  지금처럼 로그인한 사람이면 해설 파일 주소로 접근할 수 있다.
- **학생이 집에서 자기 출석을 넣는 것** — 남의 이름이나 지난 날짜로는 막았지만,
  본인·오늘 출석은 여전히 브라우저에서 만들 수 있다. 완전히 막으려면 출석 기록을
  서버 API로 옮겨야 한다 (WiFi 확인과 기록이 한 곳에서 일어나야 한다).

## 되돌린 뒤에

`rls-rollback.sql`을 실행하면 정책만 예전처럼 돌아간다. 화면에서 담당 반만 보이는
동작은 앱 코드에 있으므로 그대로 유지된다. 즉 되돌려도 교사에게 남의 반이 보이지는 않는다.
